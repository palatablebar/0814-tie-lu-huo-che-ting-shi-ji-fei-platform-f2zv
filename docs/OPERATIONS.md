# 批次操作

1. 用带异常样例做阶段预览，在「样例采信」页查看逐行处置台账：每行都有唯一处置码、原因码、来源指纹与归属结论。
2. 执行批次后查看签批闸门横幅：
   - 闸门开放表示台账数量守恒且隔离行都能归属到已知业务组，可按组签批；
   - 闸门关闭表示存在无法归属的隔离行或数量对不上，整批等待来源补齐，任何组都不能裁定。
3. 在业务阶段选中分组，查看采用的记录范围（行号、记录键、来源哈希）与异常去向。仅明确归属异常的分组被挡住，无争议组可按期签发。
4. 填写 3 至 200 字裁定意见，对单组执行签发或暂缓。提交携带幂等键，网络重试同一签批不会新增裁定；提示修订号冲突时页面会自动载入最新版本。
5. 裁定失败不改变批次修订号与既有裁定（事务回滚到旧版）。每组只保留一条裁定。
6. 导出复核证据（`review-evidence/2`）并保存于交接记录，其中可同时复核各组状态、采用记录范围与异常去向。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
